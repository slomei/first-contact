# First Contact Plugins

Plugins let you add new tools to First Contact without modifying core code. Plugins can be single `.py` files or packages (directories with `__init__.py`).

Browse community plugins in [DIRECTORY.md](DIRECTORY.md).

## Security

**Plugins run with full process access.** A plugin can import any Python module, read environment variables, access the filesystem, and modify runtime behavior. There is no sandboxing beyond cooperative conventions (read-only config copies, copied conversation history).

Always review plugin source code before installing. The community plugin directory provides a lightweight trust layer — listed plugins have been reviewed — but you are ultimately responsible for what you run.

## Quick Start

**Generate a new plugin** (recommended):

```bash
python plugin_generator.py my_plugin
python plugin_generator.py my_plugin --description "Fetches weather data"
python plugin_generator.py my_plugin --tools 3
```

This creates `plugins/my_plugin/` with `__init__.py`, `README.md`, and `plugin.json` — all correctly structured and immediately loadable.

**Or create manually:**

1. Create a `.py` file in `plugins/` (e.g. `my_plugin.py`)
2. Define the required attributes (see API Contract below)
3. Restart First Contact or run `/plugins reload`
4. Your tools are now available to the agent

## Plugin API Contract

Every plugin must export these attributes:

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `PLUGIN_NAME` | `str` | Yes | Human-readable display name |
| `TOOLS` | `list[dict]` | Yes | Tool definitions (same schema as `tools.py`) |
| `execute(tool_name, tool_input, config, conversation_history)` | `callable` | Yes | Tool handler, returns `(result_text, is_error)` |
| `PLUGIN_DESCRIPTION` | `str` | No | Short description |
| `PLUGIN_VERSION` | `str` | No | Semver version string |

### Tool Definition Schema

Each tool in the `TOOLS` list must have:

```python
{
    "name": "my_tool",              # Unique name across all plugins and core tools
    "description": "Does X.",       # What the tool does (shown to the model)
    "input_schema": {               # JSON Schema for parameters
        "type": "object",
        "properties": {
            "param": {"type": "string"},
        },
        "required": ["param"],
    },
}
```

### Execute Function

```python
def execute(tool_name, tool_input, config, conversation_history):
    """
    Parameters:
        tool_name (str): Which tool was called
        tool_input (dict): Parameters from the model
        config (dict): Read-only copy of config.json
        conversation_history (list): Read-only copy of conversation

    Returns:
        (result_string, is_error) tuple
    """
    if tool_name == "my_tool":
        return f"Result: {tool_input['param']}", False
    return f"Unknown tool: {tool_name}", True
```

## Plugin Formats

**Single file** — Drop a `.py` file in `plugins/`. Good for simple plugins. See `example_plugin.py`.

**Package** — Create a directory with `__init__.py` in `plugins/`. Generated by the template generator. Supports additional files like `README.md`, `plugin.json`, and helper modules.

Both formats are auto-discovered on startup. Files and directories starting with `_` are skipped.

## Rules

- **Tool names:** Must be unique across all plugins and core tools. Conflicts will cause unpredictable routing.
- **No core access:** Plugins receive read-only copies of config and conversation history. They cannot modify core state.
- **Error isolation:** If your plugin raises an exception, it returns an error to the agent without crashing First Contact.
- **No subprocess isolation:** Plugins run in the same Python process. Don't load untrusted code.

## Available Commands

- `/plugins` — list installed plugins with name, description, and tool count
- `/plugins reload` — re-scan the directory and reload all plugins
